​
WRF와 WPS를 컴파일할 때 종종 라이브러리 관련 에러가 나면서 exe파일이 생성이 안될 때가 있는데, 이런 경우에는 라이브러리가 없거나, 만일 있다면 경로가 잘못설정되어서 발생하는 에러가 9할이다.
​
이런경우 configure 파일에서 라이브러리 경로가 제대로 입력되어 있는지.
​
그 경로에 실제 라이브러리 파일이 있는지 확인해보자.
​
---
여담으로, 필자도 석사시절 처음 WRF를 설치할 때 라이브러리 관련 에러로 꽤나 시간을 날렸다.
​
가장 골치 아픈 것은 서로 다른 라이브러리와 WRF가 버전도 호환이 되어야 해서, 쉽게말해 조합이 맞아야 설치가 정상적으로 되기 때문에 어떤 버전이 서로 조합이 맞는 것인지 모르는 초보자 입장에서는 난감하다.
​
이런 경우, 필자는 우연히 이 모든 것을 한번에 해결할 수 있는 방법을 발견했었는데 그것은 바로 Anaconda를 이용하는 것이다.
​
Anaconda를 먼저 설치한 후, 파이썬을 설치하고 Netcdf4 모듈을 설치하면 Anaconda에서 파이썬과 Netcdf4 관련된 모듈을 자동으로 설치하면서 WRF에 필요한 들러리 라이브러리들이 자동으로 한번에 싹 설치된다.
​
필자의 경험으로는 이 방법이 가장 안전하고 확실한 방법이긴 하다.
​
하지만 더 확실한 방법은 서버를 설치해 준 업체에 모델설치를 부탁하는 것이다 ㅎ...
​
만일 스스로 모델을 다 설치해야 하는 입장이라면 Anaconda를 이용해보자.

​
WPS
- geogrid.exe : 외부에서 가져온 정적 지형자료로부터 우리나라 영역의 지상 자료를 만듭니다.
- ungrib.exe : 외부에서 가져온 GRIB 기상자료를 압축해제하고 중간 변형 파일로 압축합니다.
- metgrid.exe : 기상자료를 우리나라 영역에 맞게 수평적으로 보간합니다. 여기서 만든 자료는 real.exe 를 통하여 WRF의 입력으로 사용됩니다.
참고1) geogrid와 ungrib은 독립적이므로 실행순서에 상관이 없습니다. 참고2) ESRL에서는 WPS Domain Wizard 라는 아주 편리한 도구를 제공하고 있습니다. 영역의 구성 부터 입력자료의 준비까지 GUI 형식으로 사용할 수 있으니 꼭 한번 사용해 보세요.
​
WRF
- real.exe : 입력 자료를 모델의 연직 좌표에 맞게 수직 보간합니다.
- wrf.exe : 모델을 적분하여 예측장을 생성합니다.
​
나 같은 경우는 이번에 real.exe 단계에서 real.exe 대신 ideal.exe를 사용하면 되겠다.

> tc.exe는 언제 사용하지??

​
WRF-ARW 모델은 다음과 같이 4종류의 실행가능한 파일이 있습니다.
- ideal.exe 및 real.exe : 초기화 프로그램
- wrf.exe : 모델의 실제 적분
- ndown.exe : one-way nesting에 사용
- tc.exe : 태풍이나 허리케인 같은 열대성 저기압의 추가 또는 제거에 필요한 TC Bogusing에 사용
​
이렇다고 하는데, WRF 컴파일을 em_tropical_cyclone으로 했더니 ideal.exe 와 wrf.exe만 생성되었다.
​
https://www2.mmm.ucar.edu/wrf/OnLineTutorial/
> 🔗 **[ARW OnLine Tutorial](https://www2.mmm.ucar.edu/wrf/OnLineTutorial/)**
> Home Introduction Compilation Basics Case Studies Graphics Tools Data
> *www2.mmm.ucar.edu*

위의 튜토리얼 홈페이지를 확인해보니 em_real 로 컴파일하는 실제사례 실험의 경우에는 컴파일을 하면
​
ndown.exe: Used for one-way nesting
tc.exe: TC Bogusing for adding or removing a tropical cyclone
real.exe: WRF initialization for eal data cases
wrf.exe: WRF model integration
​
이렇게 4개의 executable이 생성된다고 한다.
​
