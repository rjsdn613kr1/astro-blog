WPS 설치 문제는 역시나 라이브러리 문제였다.
​
그리고 bash_profile에서 NETCDF를 여러개 적용되도록 했더니 마지막에 적힌 NETCDF가 적용되어 올바르게 내가 원하는 라이브러리로 작동되지 않았다.
​
그래서 필요없는 버전의 라이브러리는 전부 주석처리(#)한 후에 필요한 라이브러리만 켜놓고
```
source ~/.bash_profile
```
위 명령어로 새로고침을 한 뒤, 다시 설치하니 문제없이 설치 되었다.
​
혹시 설치과정에서 문제가 생기는 이가 있다면 반드시 configure 파일을 확인해보기 바란다.
​
튜토리얼 홈페이지에 나온대로 똑같이 따라해도 컴퓨터 환경에 따라 문제가 발생하기도 한다.
​
그래서 configure 파일에 내 컴퓨터 환경에 맞게 세팅되어 있는지. 적힌 경로에 실제 라이브러리가 있는지.
​
configure 파일에는 A버전 라이브러리 정보를 적어놓고 정작 bash_profile 에는 B버전에 관한 정보를 입력하하진 않았는지 등등.
​
환경변수 세팅을 올바르게 했는지 반드시 확인해보기 바란다. 설치과정 중 생기는 문제는 이 부류가 9할이라고 장담한다.
---
참고로 WRF나 WPS 컴파일 하다가 오류가 발생했을 때는 다음과 같이 하면 오류메세지와 소요시간 등을 확인할 수 있다.
​
본인이 아래와 같이 컴파일을 했다면 wrf.log 에 설치정보나 에러메세지가 입력되어 있을 것이다.
```
./compile em_real &> wrf.log
```
아래 명령어를 입력하면 해당 정보들을 확인할 수 있다.
```
gedit wrf.log
```

> 이상 실험(Ideal case)

em_tropical_cyclone 케이스로 WRF를 컴파일 한 뒤, 기본세팅으로 테스트를 하는 중이다...
​
이상실험은 WPS 작업(ungrib, geogrid, metgird) 작업을 할 필요가 없이 바로 WRF 폴더에서 본인이 컴파일한 케이스 디렉토리로 이동한다.
(이번 경우는 .../test/em_tropical_cyclone 가 되겠다)
​
디렉토리에 run_me_first.csh 스크립트가 있는 경우 아래 명령어로 실행해주고 (없으면 패스)
(wrf.exe 실행 중에 필요한 추가 데이터 파일에 연결됨)
```
./run_me_first.csh
```
namelist.input을 자신의 원하는 실험조건에 맞춰 수정한 다음
(이번에는 테스트이므로 따로 수정하지 않음)
```
./ideal.exe
```
위 명령어를 입력해 초기화하고 wrfinput 파일이 나오면
```
./wrf.exe
```
위 명령어를 입력해서 모델을 돌리면 끝이다.
​
---
참고로,
​
ideal.exe
tc.exe
​
위의 2개를 사용하려면 serial 로 WRF를 컴파일 해야한다고 한다.
즉, 이상실험과 모조태풍기법을 사용하려면 WRF를 serial로 컴파일 해야함.
---
​
ideal.exe 를 실행시켜서 초기화가 성공적으로 마무리되면
```
wrf: SUCCESS COMPLETE IDEAL INIT
```
라고 출력된다.
​
그리고 모델을 실행하고 표준 출력을 파일에 저장하려면 다음을 입력하면 된다.
```
./wrf.exe >& wrf.out &
```
​
./wrf.exe 가 성공적으로 마무리되면
​
wrf 출력 파일이 wrfout_d01_0001-01-01_00:00:00 이라는 파일에 기록된다.
rsl.out.* 및 rsl.error.* 파일 쌍은 모든 MPI 실행과 함께 나타난다고 하는데, 이들은 표준 출력 및 오류 파일이다. MPI 실행을 위한 실행 명령은 머신마다, 그리고 MPI 설치마다 다를 수 있다고 한다.
​
​
모델 실행이 성공하면 ' wrf.out ' 또는 rsl .*.0000 파일에 마지막으로 인쇄되는 항목은 ' wrf: SUCCESS COMPLETE WRF ' 여야 한다 . 출력 파일 wrfout_d01_0001-01-01* 및 wrfrst* 는 이름 목록 변수가 출력에 대해 지정된 방식에 따라 실행 디렉토리에 있을 것이다. 이러한 파일의 타임스탬프는 namelist 파일의 시작 시간에서 설정한대로 출력된다.

​
보거싱은 WPS 단계를 완료하고 real.exe 를 하기전에 수행하여야 한다고 나와있다.
​
real.exe는 실제사례 실험(Real case) 을 할 때 사용하는 것이다.
​
그렇다면 역시 이상실험(Ideal case) 에서는 보거싱을 할 수 없는 것인가?....
​
우선 내가 컴파일한 em_tropical_cyclone 모델은 이상태풍실험을 하기 위한 모델이라고 알고 있다.
​
그러면 보거싱을 따로 할 필요가 없는 것인가...??
​
이것을 검증하기 위해서는 이상실험모델의 output을 시각화해서 태풍이 제대로 나오는지 확인해봐야 할 것 같다.
​
보거싱을 하지 않은 실제 사례(real case) WRF 모델 실험은 태풍이 있었던 시기의 배경장을 입력값으로 넣어 모델을 돌리면 모델 결과값(output) 에 태풍이 나오기는 하지만 강도가 굉장히 약하게 나온다.
​
그래서 모델 초기장에 임의로 태풍을 강화시키는 보거싱 기법을 사용하는 것이다.
​
그런데 em_tropical_cyclone 모델은 그럴 필요가 없는 것일까? 아니면 아예 다른 걸까?
​
확인해보려면 모델 결과를 시각화해봐야 되겠다.
