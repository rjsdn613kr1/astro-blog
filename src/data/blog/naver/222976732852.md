*참고로 필자는 vscode 에서 파이썬으로 주로 작업을 한다.
​
필자는 로컬에서만 주로 작업을 했었다.
​
그리고 시간이 지날수록 원격연결에 대한 필요성을 느끼게 되었고, Github(깃허브) 에 대해서 알게 되었다.
​
하지만 깃허브를 만지다가 1년간 작업물을 전부 삭제하고 마는 일생일대의 실수를 하게 되고...
​
깃허브를 잘 안쓰게 되는 중이다...
​
그러다가 vscode를 원격서버에 연결해서 로컬처럼 쓸 수 있는 동기화 기능에 대해서 알게 되었다.
​
왜 진작 서버에 로컬과 같은 환경을 구축하지 않았을까...
​
그러면 파일이 로컬에서 삭제되어도 걱정없고, 아이피주소만 있으면 어디서든 작업할 수 있는데 말이다...
​
그래서 현재 환경세팅중이다...
​
그리고 환경을 세팅하면서 맨날 할때마다 까먹는 여러가지 유용한 점들을 정리해보려고 한다.
​
---

> 가상환경 만들기

아무래도 코딩을 하다보면 라이브러리를 설치하거나 버전을 바꾸거나 하는 일이 생기는데
​
이럴 때 가상환경을 쓰지 않고 관리자모드로 바로 설치해버리면, 다른 사람들 작업환경에 피해를 줄 수도 있다.
​
그리고 권한충돌 문제라던지 자잘한 여러가지 문제가 생길 수 있기때문에 되도록 가상환경을 만들어서 자신만의 워크스페이스를 만드는 것이 좋다.
​
가상환경을 만드는 법은 간단하다.
​
우선 자신이 작업하고자 하는 폴더로 이동한 다음,
```
python -m venv my_venv
```
위 명령어를 입력하면 현재 폴더에 my_venv 라는 폴더가 생긴다.
(꼭 그대로 따라할 필요는 없고, 자신만의 가상환경 이름을 정해서 'my_venv' 대신 입력하면 되겠다)

> 각종 라이브러리 설치

필자는 라이브러리를 설치할 때 기본적으로 conda 를 사용하는 것을 선호한다.
​
Anaconda, miniconda 둘 다 상관없다. (대부분 사람들은 용량이 작은 miniconda를 선호하는 거 같긴하다)
​

> 참고로 처음으로 conda를 설치하는 사람이라면 파이썬 3.9 버전인 conda를 받기보다는 3.8 혹은 3.7 버전으로 된 conda를 설치하는걸 추천한다. 뭐든지 최신버전은 아직 자잘한 버그가 많아서 최신버전보다는 한 두단계 아랫버전이 더 안정적이고 좋다.

​
아나콘다를 설치하게되면 conda 가상환경이 세팅되는데
​
아마 기본세팅으로 (base) 라고 계정 앞에 표시될 것이다.
​
이 상태에서는 별다른 path(경로) 입력 없이 바로 conda 명령어를 사용할 수 있게 된다.
​
그러면 우리는 "conda install 패키지이름" 를 이용해 라이브러리 패키지를 설치하면 된다.
​
​
하지만 간혹 이런 경우가 생긴다.
​
​
라이브러리를 설치하려고 명령어를 입력했는데 한참동안 기다렸더니 아래와 같은 메세지가 뜬다.
​
```
Solving environment: failed with initial frozen solve. Retrying with flexible solve.
```

> 원인

이런 경우는 conda가 최신 버전이 아닌 경우에 발생할 수 있는 에러이다.

> 해결방법

```
pip install --upgrade pip
```
```
conda update -n base conda
```
```
conda update --all
```
위 명령어들을 입력해 conda를 업데이트하고 다시 시도해보자.
​
​
​

> conda-forge를 기본채널로 변경

conda-forge 는 기본 conda 채널보다 더 많은 패키지들이 있기 때문에 기본적으로 사용하는 것이 좋다고 생각한다.
```
conda config --add channels conda-forge && conda config --set channel_priority strict
```
위 명령어를 입력하면 기본적으로 conda-forge 채널을 먼저 탐색하게 된다.
​
쉽게말하면 패키지를 다운받을 기본채널을 좀 더 좋은(?) 채널로 변경하는 것이라고 생각하면 된다.

*추가 내용

> conda-forge 채널을 추가했더니 라이브러리 업데이트 및 설치가 안돼요!

​
간혹 위를 따라서 conda-forge를 기본채널로 설정하였는데 설정하고나서부터 라이브러리 설치 및 업데이트가 안되는 경우가 생길 수도 있다.
​
정확한 원인은 모르겠으나, 해결방법은 conda-forge 채널을 삭제하고 다시 기본채널만 사용하면 된다.
​
우선 아래 명령어를 입력하여 채널을 확인하자.
​
두 개중 아무거나 써도 상관없는데, 위에 명령어는 채널의 우선순위가 출력되고, 아래 명령어는 그냥 채널 리스트만 출력된다.
```
conda config --get channels
conda config --show channels
```
​
그런 다음 아래 명령어로 conda-forge 채널을 삭제해주면 된다.
​
```
conda config --remove channels conda-forge
```
​
이렇게하면 다시 기본채널을 사용하게 되어 문제가 해결된다.
​
​
​
그리고 기본채널로 설치가 안되는 패키지지가 생길 때만 아래와 같이 conda-forge 채널을 사용하면 되겠다.
```
conda install -c conda-forge 패키지이름름
```
